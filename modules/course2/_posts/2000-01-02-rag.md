## Module 2.2: Retrieval-Augmented Generation (RAG)

### The Need for RAG

While large language models are powerful, they have limitations:

* **Knowledge Cutoff**: Training data becomes stale over time
* **Hallucinations**: May generate plausible but incorrect information
* **Domain Specificity**: Lack specialized knowledge for niche domains
* **Attribution**: Cannot cite sources for their outputs

Retrieval-Augmented Generation (RAG) addresses these issues by combining neural generation with information retrieval.

### The RAG Pipeline

A typical RAG system follows these steps:

1. **Query Processing**: User query is encoded into a representation suitable for retrieval
2. **Document Retrieval**: Relevant documents are retrieved from a knowledge base
3. **Context Construction**: Retrieved documents are formatted and combined with the query
4. **Generation**: LLM generates response conditioned on both query and retrieved context
5. **Post-Processing**: Optional ranking, filtering, or citation extraction

### Retrieval Strategies

Different approaches can be used to retrieve relevant documents:

#### Sparse Retrieval

**Sparse retrieval** uses traditional information retrieval methods:

* **TF-IDF**: Term Frequency-Inverse Document Frequency scoring
* **BM25**: Probabilistic ranking function with parameters $$k_1$$ (term saturation) and $$b$$ (length normalization)
* **Advantages**: Fast, interpretable, no training required
* **Disadvantages**: Vocabulary mismatch problem, no semantic understanding

#### Dense Retrieval

**Dense retrieval** uses neural embeddings:

* Encode queries and documents as dense vectors
* Use cosine similarity or dot product for scoring
* Common models: Sentence-BERT, DPR (Dense Passage Retrieval), Contriever
* **Advantages**: Captures semantic similarity, handles paraphrases
* **Disadvantages**: Requires training, computationally expensive

#### Hybrid Retrieval

**Hybrid retrieval** combines sparse and dense approaches:

* Run both retrieval methods in parallel
* Combine scores using learned or heuristic weights
* **Advantages**: Best of both worlds - semantic understanding and exact matching
* **Use Cases**: Enterprise search, question answering, code search

### Vector Databases

RAG systems rely on efficient vector databases for dense retrieval:

* **Popular Options**: Pinecone, Weaviate, Milvus, Qdrant, FAISS, Chroma
* **Key Features**:
  * Approximate nearest neighbor (ANN) search
  * Horizontal scaling
  * Metadata filtering
  * Real-time indexing

### Chunking Strategies

Breaking documents into chunks is crucial for effective RAG:

* **Fixed-Size Chunks**: Simple but may break semantic units
* **Sentence/Paragraph-Based**: Preserves natural boundaries
* **Semantic Chunking**: Uses embeddings to group related content
* **Hierarchical Chunking**: Multi-level representations for different granularities

### Advanced RAG Techniques

Modern RAG systems employ sophisticated enhancements:

#### Query Rewriting

* Transform user queries for better retrieval
* Generate multiple query variations
* Use LLM to expand or clarify queries

#### Reranking

* Initial retrieval gets top-k candidates (e.g., k=100)
* Cross-encoder model reranks based on query-document relevance
* Reduces false positives from first-stage retrieval

#### Multi-Hop Retrieval

* Iteratively retrieve and reason over multiple documents
* Follow chains of reasoning across knowledge base
* Essential for complex questions requiring synthesis

#### Self-RAG

* LLM decides when to retrieve additional information
* Generates critique and reflection tokens
* Improves factuality and reduces unnecessary retrieval

### Evaluation Metrics

RAG systems are evaluated on multiple dimensions:

* **Retrieval Quality**: Recall@k, MRR (Mean Reciprocal Rank), NDCG
* **Generation Quality**: Faithfulness, relevance, fluency
* **End-to-End Performance**: Task-specific metrics (accuracy, F1, etc.)
* **Latency**: Time from query to response

### Challenges and Trade-offs

* **Context Length**: Limited by LLM's maximum context window
* **Retrieval Noise**: Irrelevant documents can hurt generation quality
* **Computational Cost**: Embedding and retrieval add overhead
* **Freshness**: Keeping vector database synchronized with source data
