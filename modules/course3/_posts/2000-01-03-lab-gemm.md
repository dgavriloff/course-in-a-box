## Module 3.3: Lab Project - Optimizing GEMM

### Project Overview

In this lab, you will implement and optimize **GEMM** (General Matrix Multiplication), one of the most important operations in deep learning. Matrix multiplication $$C = AB$$ is at the heart of:

* Neural network forward and backward passes
* Attention mechanisms in Transformers
* Embedding lookups and projections
* Batch processing

Your goal is to progressively optimize a naive implementation to approach the performance of highly-tuned libraries like cuBLAS.

### Learning Objectives

* Apply memory coalescing principles
* Implement shared memory tiling
* Handle bank conflicts
* Optimize for different matrix sizes
* Profile and measure performance improvements

### Implementation Steps

You will implement GEMM through progressive optimization:

1. **Naive Implementation**
   * Start with a straightforward implementation
   * Each thread computes one element of output matrix C
   * Load elements directly from global memory
   * **Expected Performance**: ~10-50 GFLOPS (baseline)
   * **Key Learning**: Understanding basic kernel structure

2. **Tiled Implementation with Shared Memory**
   * Divide matrices into tiles (e.g., 16x16 or 32x32)
   * Load tiles into shared memory
   * Reuse loaded data across multiple computations
   * Add synchronization barriers (`__syncthreads()`)
   * **Expected Performance**: ~500-1000 GFLOPS (10-50x speedup)
   * **Key Learning**: Data reuse dramatically improves performance

3. **Coalesced Memory Access**
   * Ensure threads in a warp load consecutive memory locations
   * Transpose matrix access patterns if needed
   * Pad shared memory to avoid bank conflicts
   * **Expected Performance**: ~1000-2000 GFLOPS (2x speedup)
   * **Key Learning**: Memory access patterns matter as much as computation

4. **Register Blocking and Vectorization**
   * Each thread computes multiple output elements (e.g., 4x4 or 8x8 sub-tile)
   * Use vector loads (`float4`) where possible
   * Increase arithmetic intensity (compute-to-memory ratio)
   * **Expected Performance**: ~3000-6000 GFLOPS (2-3x speedup)
   * **Key Learning**: Maximizing register usage and reducing memory traffic

### Starter Code Structure

```cuda
// Naive GEMM kernel
__global__ void gemmNaive(float* A, float* B, float* C, int M, int N, int K) {
    int row = blockIdx.y * blockDim.y + threadIdx.y;
    int col = blockIdx.x * blockDim.x + threadIdx.x;
    
    if (row < M && col < N) {
        float sum = 0.0f;
        for (int k = 0; k < K; k++) {
            sum += A[row * K + k] * B[k * N + col];
        }
        C[row * N + col] = sum;
    }
}
```

### Performance Metrics

You should measure:

* **GFLOPS** (Giga Floating-Point Operations Per Second)
  * Formula: `(2 * M * N * K) / (time_in_seconds * 1e9)`
  * Compare against cuBLAS performance
  
* **Memory Bandwidth Utilization**
  * Theoretical peak vs. achieved bandwidth
  * Use NVIDIA Nsight Compute to profile
  
* **Occupancy**
  * Active warps vs. maximum possible warps
  * Balance with register and shared memory usage
